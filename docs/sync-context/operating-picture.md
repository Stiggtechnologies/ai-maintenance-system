## Scoped operating API checkpoint — October 10, 2026

It never falls back to unscoped reads or invented empty data.

The server requires an authenticated same-tenant profile and an allowlisted role. A non-null site must belong to that tenant; missing and foreign sites have the same refusal. This is **tenant/role authorization plus canonical site selection**, not an invented individual site-membership permission model. Membership follows canonical site/asset, route/segment, work, evidence/recommendation/decision/approval, readable risk, Recovery, Develop and capital-project relations. Audit JSON and coordinate proximity never establish membership. Same-link site contradictions are refused; separate consistent links can deliberately represent multiple sites. Whole-link risk privacy and inherited work/approval risks are checked before projection.

Objects require current independently verified feature/evidence records, ordered finite observation/verification times, explicit coordinate provenance, visible canonical subjects and separate source-rights/health gates. Disabled/inactive connectors cannot emit. Strict check/observation times apply at read time without rewriting ingress telemetry; stale/degraded sources can emit last-known verified geometry but are never labelled live. Feature events reuse eligible geometry predicates; work history remains unlocated, with approval facts evaluated as-of the event. This is not history replay or event-location inference.

Object limits are 1–500, event limits 0–500. `candidateCount` and legacy `recordCount` are the scoped role/risk-visible active **pre-gate population**; `eligibleCount` is post-gate/pre-limit, never rendered count. Object exclusions are disjoint in declared order: draft, expired, scope conflict, unlinked, source missing, rights, health, invalid time/validity, coordinates, payload budget, evidence. An unavailable layer can have candidates but zero eligible rows: it is **not empty**. The parser reconciles layer, event and object totals, exclusions, returned counts and exact limits. Scope conflicts do not silently disappear; ordinary out-of-site rows and unreadable relationships are outside this scoped population.

Technical response budgets do not certify engineering suitability: at most 500 dependent sources; bounded source text, 256 subjects/evidence/missing-evidence entries per emitted feature, 64 KiB source geometry and a conservative 128 KiB escaped-wire upper bound per feature. Work titles are bounded to 4,000 characters / 16 KiB. A conservative cumulative 8 MiB budget refuses the whole query **before** allocating returned JSON projections; the final exact-byte check is defense in depth. Conservative estimates may refuse a query smaller than 8 MiB; callers must narrow scope/lower explicit limits, never silently lose evidence. Event counts/sorts carry fixed-width identities and times; event JSON and as-of approval lookups are constructed only for limited returned candidates. These bounds limit projection allocation, not the database's need to scan/count the authorized population. Oversized features receive `payloadBlocked`; over-budget source metadata or complete responses are controlled refusals. Geometry output is an explicit type/coordinates projection, not arbitrary provider properties.

### What the input contract does not prove

- A supplied source-coordinate basis is a description, not authenticated survey evidence. Numeric geometry validity does not prove survey suitability, polygon topology, winding, non-degeneracy or a safe industrial boundary. The structural rules follow [RFC 7946](https://www.rfc-editor.org/rfc/rfc7946); engineering suitability still requires canonical evidence and authorized review.
- A UUID-shaped site scope is not proof of site authorization or membership. The server must resolve the caller's tenant and permitted site and derive membership through canonical links, never coordinate proximity.
- Query `eligible`, `returned`, exclusion and truncation counts must come from the actual server predicates. They are not a count of rendered markers or a promise of complete enterprise coverage. Client rejection does not change server coverage metadata; issues and rendered counts remain separate.
- Source class and authority are preserved independently. No tuple of metadata authorizes dispatch, safety decisions, work release, approvals or an engineering conclusion.
- Events in this contract are unlocated canonical context, explicitly `locationAvailable: false`. Work history is not assigned an asset centroid or another invented location.
- Known coordinates do not make an external provider commercially licensed or a customer feed live. Legal rights and actual source health remain separate gates.
